## 1. Defect Description
Optical character casing and normalization flaw for automotive vehicle number plates. When analyzing vehicle license plates containing Maharashtra state registration codes (e.g., `MH 12 AB 1234`), the deep learning OCR sequence model erroneously predicted the letters as `Mh` (capital M, lowercase h) instead of official uppercase `MH`. In vehicle registration and traffic surveillance systems, all registration marks are legally required to be strictly uppercase. The extraction of `Mh` resulted in downstream database lookup failures and unstandardized plate exports.

## 2. Steps to Reproduce
1. In the Streamlit dashboard, select the 1-Click Benchmark Demo for "Vehicle Number Plate" or upload a photo with license plate text `MH 12 AB 1234` or standalone `MH`.
2. Observe the extracted text in the "Extracted Characters" text box.
3. Notice that the state code appears as `Mh 12 AB 1234` or standalone `Mh`.
4. Observe that downstream database queries for registration records fail due to case-sensitive mismatch against canonical state registry records.

## 3. Expected vs. Actual Behavior
- **Expected:** All vehicle registration letters, including the Maharashtra state prefix `MH`, must be recognized and extracted strictly as uppercase `MH`.
- **Actual:** The OCR model extracted the characters as mixed-case `Mh`, and the post-processing pipeline failed to normalize it.

## 4. Root Cause Analysis
1. In deep learning character sequence recognition (CRAFT + CRNN / EasyOCR), the glyph structures for uppercase `H` and lowercase `h` exhibit near-identical vertical stroke activations under certain font weights, causing the neural network to output lowercase `h`.
2. The existing `disambiguate_license_plate()` function in `src/ocr_engine.py` had a narrow regular expression that strictly expected a single continuous 10-character alphanumeric string (`MH12AB1234`).
3. Whenever a license plate was split across two rows (e.g. top row `MH 12`, bottom row `AB 1234`), had hyphens/spaces, was presented as a partial plate, or was detected in a standalone block (`MH`), the 10-character regex failed to match. The function bypassed all correction and returned the raw OCR string as-is: `Mh`.

## 5. Developer Resolution (Applied by Software Developer Agent)
- Upgraded `disambiguate_license_plate()` in `src/ocr_engine.py` with an exhaustive multi-tier contextual disambiguation engine:
  - **Official State Registry Integration:** Registered all 36 official state and Union Territory codes per the Indian Motor Vehicles Act (`MH`, `DL`, `KA`, `HR`, `TN`, `KL`, etc.).
  - **Standalone State Code Matching:** Any standalone block matching `Mh`, `mh`, or `mH` instantly resolves to canonical uppercase **`MH`**.
  - **Two-Line Header & Partial Matching:** Two-line headers (e.g. `Mh 12`, `mh 12`, `Mh-12`) resolve to canonical **`MH 12`**. Full and partial plate formats (`Mh 12 AB 1234`) resolve cleanly to **`MH 12 AB 1234`**.
  - **Token Boundary Regex Normalization:** Added regex boundary replacement (`\b[mM][hH](?=[\s\-_0-9]|$)`) to enforce uppercase `MH` across all alphanumeric tokens while preserving non-state words (e.g., `SPEED LIMIT 25 MPH`).
