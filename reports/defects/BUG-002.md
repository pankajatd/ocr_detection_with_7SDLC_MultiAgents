## 1. Defect Description
Multi-column text jumbling and line interleaving in structured business documents, invoices, and thermal store receipts. When processing documents structured in two or more vertical columns (e.g. food item name on the left and price on the right), naive sorting of detected bounding boxes ordered text blocks strictly by raw vertical pixel coordinate `y_min`. Because characters on the same printed line often have slight 2-to-3-pixel vertical baseline variations, words from adjacent lines were interleaved out of order (e.g. `MILK 1L ➔ SOURDOUGH BREAD ➔ $3.50 ➔ $3.80`), completely destroying line-item pairing and financial integrity.

## 2. Steps to Reproduce
1. In the Streamlit dashboard, select the 1-Click Benchmark Demo for "Store Receipt" (`demo_type="store_receipt"`).
2. Examine the extracted text output.
3. Observe that instead of pairing item names with their corresponding prices on the same line, item names from successive lines were clumped together, and prices were grouped separately at the end.
4. Downstream accounting and expense parsing engines failed because the line-by-line item-price association was destroyed.

## 3. Expected vs. Actual Behavior
- **Expected:** Text blocks belonging to the same horizontal row must be read together in natural reading order (left-to-right) before moving down to the subsequent row (`MILK 1L  $3.50 \n SOURDOUGH BREAD  $3.80`).
- **Actual:** Vertical jitter caused words across different lines to interleave and jumble based on tiny sub-pixel baseline offsets.

## 4. Root Cause Analysis
In `src/ocr_engine.py`, raw bounding boxes from the CRAFT detector were sorted using an unquantized key: `(box_y_min, box_x_min)`. If the second line's text item started at `y = 124.8` and the first line's right-column price ended at `y = 125.1`, the sorting algorithm placed line 2's item ahead of line 1's price. The engine lacked a line-clustering quantization mechanism to group nearby horizontal boxes into common row bands.

## 5. Developer Resolution (Applied by Software Developer Agent)
- Implemented an **Adaptive Line Band Clustering Engine** in `src/ocr_engine.py`:
  - Quantizes the vertical coordinate of all bounding boxes into discrete 25-pixel horizontal row bands:
    $$\text{line\_key} = \left(\left\lfloor \frac{y_{\min}}{25} \right\rfloor \times 25, \; x_{\min}\right)$$
  - Any bounding boxes falling within the same 25-pixel vertical envelope are snapped to the same logical row band.
  - Inside each row band, boxes are sorted strictly from left-to-right (`x_min`), ensuring line-item names precede their prices.
  - Only after an entire horizontal band is fully processed does the engine advance to the next line.
